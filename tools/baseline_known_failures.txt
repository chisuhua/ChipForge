# tools/baseline_known_failures.txt
#
# ★★★ **baseline-known 失败清单**（★ C1「旧产物顶替」假绿通道排查的产物）
#
# ---------------------------------------------------------------------------
# ★ 语义（★ 由 `tools/run_catch2_with_baseline.sh` 强制）
# ---------------------------------------------------------------------------
# ★ 失败集合 **⊆ 本清单** ⇒ ★ 退出码 **0**（★ 「无新回归」）
# ★ 失败集合 **⊋ 本清单** ⇒ ★ 退出码 **非 0**（★ 有**新回归** ⇒ fail-closed）
# ★ ★ **纪律**：★ 清单条目**不是**「允许失败」的空白支票 ⇒ ★ 每条 MUST 附
# ★   「根因 + owner + 收敛期限」⇒ ★ 清单本身也要被 review（★ 同 ADR-089
# ★   例外白名单的纪律：★ 不得靠扩张清单来消红）。
#
# ★★★ **为何需要它**（★ C1 的实测结论）
# ---------------------------------------------------------------------------
# ★ `ctest` 的 `chipforge_tests` entry 跑的是**全量** Catch2 binary
# ⇒ ★ 它包含下面的 baseline-known 失败 ⇒ ★ **该 entry 恒红**
# ⇒ ⇒ ★ 「全量回归通过」这个信号**从来就不存在**
# ⇒ ⇒ ★ 任何依赖 ctest 退出码的判断（CI / 脚本 / 人工）都在**误判**。
# ⇒ ⇒ ★ 修法：★ 引入本清单 + `run_catch2_with_baseline.sh`（★ 判定「是否有
# ★   **新**失败」而非「是否有任何失败」）⇒ ★ 让退出码**重新有意义**。
#
# ---------------------------------------------------------------------------
# ★ 格式：★ 按 **binary** 分节（★ `[tlm]` / `[chmem]`）⇒ ★ 每节内每行一个
#   Catch2 **test case 名**（不含 tag）⇒ ★ `#` 开头为注释
#   ⇒ ★ 分节的意义：★ 「清单里有、本次未失败」的检查**只在对应 binary 内**做
#   ⇒ ★ 否则跑 TLM 子集时会把 CH_MEM 的条目误报为「可能已修复」
# ---------------------------------------------------------------------------
