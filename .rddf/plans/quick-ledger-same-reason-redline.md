**Goal**: 补齐 `tools/check_coverage_parity_ledger.sh` 的「同一理由 ≤10 次」红线机检 —— 已归档 spec `openspec/specs/tlm-coverage-parity-ledger/spec.md` 的 Requirement `tlm-coverage-parity-ledger-red-lines` 明确要求「同一理由出现 MUST ≤10 次」且其 Scenario 明确要求「脚本报错并**列出违规条目**」，但脚本**仅声明 `MAX_SAME_REASON=10` 常量而从未使用** ⇒ 属既有 spec 的**实现缺口**（非新功能）。同时补一条相邻校验：not-covered 条目的理由列**必须**是显式手写理由（不得为继承标记），否则等于没写理由。

**Architecture**: 在既有「③ 红线」段内追加两个子检查（③-b 同一理由分组计数 / ③-c 显式理由校验），沿用脚本现有的 `VIOL=1` 聚合 + `exit 1` 语义与 CI warn 级接入（不动 CI 配置）。理由列抽取沿用脚本既有口径（`grep -E` 定位条目行 → `awk -F'|'` 取 `$6`，因 `$1` 是首个 `|` 前的空串，`$6` 即 markdown 第 5 列）。分组按**完全相同的理由字符串**（仅去首尾空白）计数 —— 字面口径，理由文本内的 `|` 需按 awk 字段切分的安全方式处理（见 Task 2 Step 2 的实测）。

**Tech Stack**: Bash + awk（零新依赖）· Markdown 台账 · **零生产代码改动**（不碰 `ip/` `src/` `tests/`）。

**上游 SSOT**: ADR-088 §4（台账三态格式 + 红线定义）· 已归档 spec `tlm-coverage-parity-ledger-red-lines` · 台账 `docs/architecture/tlm-coverage-parity-ledger.md` §7「已知实现缺口」登记项。

**复杂度分诊（P1）**: **simple**（单模块 `tools/`、无公开 API 影响、AC 可机械验证、`git checkout` 完全可逆）。已派 **Oracle** 做技术审阅（边界情况 / 归一化取舍 / 误报风险），结论并入 Task 2。
